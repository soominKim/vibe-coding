chapter 12lesson 12.2private

서비스 보안 점검하기

보안 점검 돌려보기

앞선 레슨에서 정리한 체크리스트를 보안 점검 프롬프트로 먼저 돌려보고, 반복 점검에 쓸 수 있는 skill로 바꿉니다.

얻어갈 것

  • 앞선 레슨에서 정리한 체크리스트를 보안 점검 프롬프트로 먼저 돌려봅니다.
  • 같은 점검을 반복할 수 있도록 Superpowers의 writing-skills로 프로젝트 전용 보안 점검 skill을 만듭니다.

기존 프롬프트로 먼저 점검하기

처음부터 skill을 만들 필요는 없습니다. 먼저 앞 레슨의 체크리스트를 프롬프트로 넘겨서, AI가 어떤 위험 항목을 잡아내는지 확인합니다. 이 단계에서 점검 범위와 결과 형식이 괜찮은지 봐야, 다음에 만들 skill도 쓸모 있어집니다.

P1보안 점검 프롬프트 실행하기
현재 프로젝트를 런칭 전 보안 관점에서 점검해줘.

1. 사용자 권한 관점
- API·Server Action의 인증·인가 누락
- 다른 사용자의 데이터나 파일에 접근 가능한지 (Supabase면 RLS 포함)
- 관리자 화면과 관리자 API 접근 제어
- 요청 body를 통째로 반영하거나, 응답에 화면 밖 개인정보까지 내려주는지

2. 우리 서비스 관점
- API 키·환경변수·오류 응답으로 민감 정보 노출
- rate limit과 과금 상한 (로그인, AI 호출 등)
- 운영 환경과 로컬 환경 분리
- 백업·복구, 사고 대응(키 재발급·기능 잠금), 이상 감지 알림

고칠 코드를 바로 만들기보다, 위험한 항목과 실패 테스트를 먼저 정리하고 바로 고칠 것과 사람이 결정할 것을 나눠줘.

결과를 볼 때는 세 가지를 확인합니다.

  • 위험 항목이 "무엇이 위험한지"보다 "어떻게 확인할지"까지 적혀 있는지 봅니다.
  • 정상 동작 테스트만 있으면 부족합니다. 권한 밖 요청이 실패하는 테스트가 있어야 합니다.
  • 바로 고칠 항목과 운영자가 결정할 항목이 섞여 있으면 따로 나눕니다.

보안 점검 프롬프트는 만능 보안 도구가 아니라 반복 점검의 출발점입니다. 특히 권한 문제는 정상 동작 테스트만으로는 부족합니다. 남의 데이터, 관리자 API, private 파일처럼 권한 밖 요청이 실패하는 테스트가 있어야 합니다. 이 부분은 테스트 코드를 더 고도화하면 충분히 커버할 수 있습니다.

반복 점검 SKILL로 만들기

P1을 한 번 돌려보고 점검 방향이 맞으면, 그다음에는 같은 기준을 반복해서 쓰는 skill로 만듭니다. 이 skill은 시작하자마자 점검 방식을 먼저 묻게 만듭니다. 어떤 방식을 고르든 코드베이스 정적 검사는 포함하고, 실제 요청은 선택한 경우에만 보냅니다.

부록 B에서 설치한 Superpowers에는 skill을 만들어주는 writing-skills가 들어 있습니다. (아직 설치하지 않았다면 부록 B.1을 참고해 Claude Code 입력창에서 /plugin install superpowers@claude-plugins-official을 먼저 실행하세요.)

Claude Code에서 /superpowers:writing-skills를 열고, 아래 P2처럼 요청합니다. 여기서 목표는 코드 수정을 바로 시키는 것이 아니라, 앞에서 돌려본 보안 점검 흐름을 반복 가능한 skill로 저장하는 것입니다.

P2보안 점검 skill 만들기
/superpowers:writing-skills

현재 프로젝트에 붙일 보안 점검 skill을 만들어줘.
시작하면 먼저 점검 방식을 물어봐.

"어떤 방식으로 보안 점검을 진행할까요?
1. 운영/Preview URL을 직접 테스트
2. 로컬 서버를 켜서 테스트
3. 로컬 코드만 점검"

방식이 정해지면 항상 코드베이스 정적 검사부터 해줘.
- 라우트, API, 권한 경계, 환경변수 사용, 데이터 접근 패턴을 읽고 사용자 권한 관점과 우리 서비스 관점으로 나눠서 정리해줘.
- 사용자 권한 관점에서는 인증·인가, 소유자 확인, 관리자 접근, 파일 접근, RLS, 입출력 필드 제한을 봐줘.
- 우리 서비스 관점에서는 API 키·환경변수 노출, 오류 응답, rate limit과 과금 상한, 환경 분리, 백업·복구, 사고 대응을 봐줘.

운영/Preview URL 모드에서는 URL 소유와 점검 허가를 확인한 뒤 curl이나 브라우저로 비파괴 요청만 보내줘.
로컬 서버 모드에서는 필요한 dev server를 켜고 localhost 기준으로 같은 요청을 보내줘.
로컬 코드만 점검하는 모드에서는 실제 HTTP 요청 없이 위험 후보와 작성해야 할 실패 테스트만 정리해줘.

동적 점검은 비로그인 상태의 보호 페이지 접근, 일반 사용자로 관리자 경로와 관리자 API 접근, id나 path를 바꾼 남의 데이터 접근, private 파일 직접 URL 접근, 오류 응답의 민감 정보 노출, 가벼운 rate limit 확인 정도로 제한해줘.
대량 요청, 파괴적 요청, 실제 데이터 변경은 하지 마.

결과 형식은 "바로 고칠 것 / 사람이 결정할 것 / 반복 점검할 것"으로 해줘.

추가적으로 점검 skill을 찾는다면 이 두 가지를 참고할 만합니다.

  • claude-code-security-review — PR 단위로 자동 점검하는 Claude Code용 GitHub Action.
  • vibe-security — vibe-coding 앱에서 자주 나오는 실수(rate limit, 요청 데이터 검증, 결제 검증 등)에 초점을 맞춘 skill.
