지도 데이터베이스 구축하기

데이터베이스 복습 퀴즈

관계형 데이터베이스 스키마 설계와 Supabase, 마이그레이션 내용을 퀴즈로 복습합니다. 보기를 클릭하면 정답과 해설이 나타납니다.

Q1관계형 데이터베이스 스키마 설계 시, JSON 객체의 키는 주로 무엇으로 변환될까요?

JSON 객체는 { "name": "...", "lat": 37.5, "photos": [...] }처럼 키-값 구조입니다. 이걸 관계형 테이블로 옮기면 각 키가 열(컬럼) 이름이 되고, 하나의 객체(레코드)는 한 행(row)이 됩니다. 즉 name·lat·photos 같은 키가 places 테이블의 컬럼으로 매핑됩니다. 테이블명은 데이터의 종류(예: places)에서, 데이터 타입은 값의 형태에서 따로 정해집니다.

Q2이번 챕터에서 사용한 Supabase는 어떤 데이터베이스를 기반으로 하나요?

Supabase는 PostgreSQL(Postgres)를 중심에 두고, 그 위에 인증(Auth)·파일 저장소(Storage)·API 접근 기능을 묶어 제공하는 백엔드 서비스입니다. 그래서 우리가 만든 places 테이블도 결국 Postgres 테이블이며, 평소 쓰던 SQL과 관계형 개념이 그대로 적용됩니다.

Q3기존 cafes.json을 읽던 서비스 코드를 Supabase places 테이블에서 읽도록 바꾼 뒤, 반드시 확인해야 할 것은?

이 작업의 핵심은 데이터의 출처(로컬 JSON → Supabase)만 바꾸고, 화면 동작은 그대로 유지하는 것입니다. 따라서 전환 후에는 지도 마커와 카드 목록이 기존과 똑같이 보이고 동작하는지를 먼저 검증해야 합니다. 화면이 깨지지 않으면서 데이터만 DB에서 오도록 바뀌었다면 마이그레이션이 성공한 것입니다.
