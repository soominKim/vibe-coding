chapter 11lesson 11.2private

장소 수집을 위한 크롤링

브라우저 자동화를 통해 장소 후보 수집하기

Claude Code에 Claude in Chrome을 연결해 검색 결과에서 장소 후보 URL을 모으고, 사람이 검수한 것만 관리자 페이지에서 등록합니다.

얻어갈 것

  • Claude in Chrome을 설치하고 Claude Code에 연결해, 평소 쓰는 크롬을 에이전트에게 맡길 수 있습니다.
  • 느좋카페의 후보가 될 수 있는 장소들을 수집하고 확인해 봅니다.

어떻게 긁을 것인가

  • Claude Code에게 브라우저를 맡기고 일을 시키는 방식으로 갑니다. 이번에 쓸 도구는 Claude in Chrome입니다.
  • Claude in Chrome은 실제 우리가 사용하는 Chrome을 조작할 수 있도록 도와줍니다. 크롬 확장 하나만 설치하면 별도 도구 세팅이 없습니다.

Claude in Chrome 연결하기

  • 크롬(또는 엣지) 브라우저에서 Claude in Chrome 확장 프로그램을 설치해주세요.
  • 확장을 설치했으면, 터미널에서 Claude Code를 브라우저 연동 상태로 시작합니다.
Terminal
$claude --chrome  # 크롬 연동을 켠 상태로 Claude Code 시작
$/chrome  # 이미 열려 있는 세션이라면 이 명령으로 연동·연결 상태 확인
  • 첫 브라우저 작업을 시키면 권한 승인을 물어봅니다. 승인하면 새 탭이 열리고, agent가 일하는 모습이 크롬 창에 실시간으로 보입니다.
  • 로그인 페이지나 CAPTCHA를 만나면 agent가 멈추고 사람에게 넘깁니다. 직접 처리해 주고 이어서 시키면 됩니다.
  • 연결이 안 잡히면 크롬을 재시작한 뒤 /chrome에서 "확장 프로그램 다시 연결"을 선택합니다.

브라우저를 직접 조작하면서 화면을 확인하는 작업은 일반 대화보다 토큰을 훨씬 많이 씁니다. 이런 크롤링 작업은 Opus 같은 고성능 모델보다 Sonnet 같은 가벼운 모델로도 충분한 경우가 많으니, 비용이 신경 쓰인다면 모델을 낮춰서 시켜보는 것도 방법입니다.

1단계 — URL 후보 모으기

  • 검색어는 "노트북하기 좋은 OOO 카페" 패턴으로 갑니다. OOO에는 지금 서비스하려는 동네를 넣습니다. 예: "노트북하기 좋은 석촌호수 카페".
  • agent에게 시키는 건 검색과 URL 수집까지입니다. 본문·리뷰·사진은 긁지 않습니다.
  • 사람이 사용하는 브라우저를 기준으로 동작하기에 무리한 동작을 하지 않는 이상 봇 탐지(Bot Detection)에 걸리지 않습니다.
P1구글 검색 결과에서 장소 후보 URL 모으기
크롬으로 구글에 "노트북하기 좋은 OOO 카페"를 검색해서, 결과에 나오는 장소 페이지 URL을 20개쯤 모아줘.

- 장소 이름 + URL만 리스트로 정리해줘.
- 로그인이 필요한 페이지가 나오면 건너뛰어줘

크롤링 된 후보 URL들은 data/crawling/ 폴더에 {YYYYMM}-{장소}.md로 제목,URL로 정리해줘

2단계 — 내가 검수하기

  • 받은 URL을 몇 개씩 직접 열어 봅니다. 실제로 있는 곳인지, 노트북 작업에 맞는 곳인지는 사람이 판단합니다.
  • 지금 서비스 지역이 아니거나, 폐업했거나, 성격이 안 맞는 곳은 여기서 걸러냅니다.

3단계 — 관리자 페이지에서 등록하기

  • 검수를 통과한 장소만, 느좋카페 관리자 페이지에서 직접 등록합니다. 이름·주소 같은 사실 정보만 넣습니다.
  • 리뷰 원문이나 남의 사진은 옮기지 않습니다. 태그는 내가 판단해서 답니다.
  • 등록한 뒤에는 지도에서 위치가 맞게 찍히는지 몇 개 열어 확인합니다.
