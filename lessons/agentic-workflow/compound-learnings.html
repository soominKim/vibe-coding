에이전틱 워크플로우

배운 걸 프로젝트에 남기기

learn으로 배운 규칙 후보를 추리고 CLAUDE.md, 체크리스트, Skill에 최소 반영하는 방법

얻어갈 것

  • 한 번 해결한 문제를 다음 작업에서 다시 설명하지 않게 만드는 단계를 봅니다.
  • learn으로 배운 점을 어디에 남길지 나누고, 장소 피드백 작업에 이어 적용합니다.

왜 마지막에 학습이 붙나

clarify -> prd -> implement -> verify or code-review까지 오면 기능은 끝납니다.

  • 세션이 바뀌면 AI는 이전 맥락을 잊습니다.
  • 검증 중 발견한 실수, 꼭 돌릴 명령, 건드리면 안 되는 파일은 프로젝트 파일에 남겨야 합니다.
  • learn은 이번 작업에서 배운 것을 다음 작업의 기본값으로 바꾸는 단계입니다.

이 단계를 영어로 compounding(복리처럼 쌓인다)이라고 부릅니다. 한 작업의 교훈이 다음 작업의 출발점이 되어, 반복할수록 점점 에이전트가 똑똑해지는 구조입니다.

무엇을 남기고 무엇을 버리나

모든 일을 다 남기면 CLAUDE.md가 금방 잡동사니가 됩니다. 남길 후보는 보통 네 가지입니다.

  • 반복된 실수: 같은 문제가 두 번 이상 나왔다면 규칙 후보입니다. 한 번뿐인 사고는 남기지 않습니다.
  • 검증 명령: npm run build, 특정 smoke test처럼 이 프로젝트에서 작업 후 꼭 돌려야 하는 명령입니다.
  • 금지 사항: 비밀키 노출, 생성물 커밋, 위험한 reset처럼 피해야 할 행동입니다.
  • 프로젝트 판단: 이 프로젝트에서는 어떤 구조, 파일, 도구를 우선하는지에 대한 결정입니다.

남길 곳도 성격에 따라 나눕니다.

  • CLAUDE.md: Claude Code가 이 프로젝트에서 먼저 읽을 짧은 작업 규칙. 한두 줄로 끝나는 것만 둡니다.
  • 별도 문서(docs/ 등): 배포 절차, 데이터 작업 규칙처럼 CLAUDE.md에 넣기엔 긴 내용을 둡니다.
  • 체크리스트: 작업 전후에 사람이 빠르게 훑을 항목입니다.
  • Skill: 같은 흐름에서 반복해서 문제가 생기면 해당 Skill의 SKILL.md를 고치거나 반복되는 워크플로우는 스킬로 만듭니다.

learn으로 이어서 돌려보기

긴 작업 태워보기에서 장소 피드백 작업을 PR까지 올렸다면, 같은 세션에서 바로 learn을 돌립니다. learn은 바뀐 것과 검증 중에 막혔던 지점을 돌아보고, 재사용할 만한 것을 추립니다.

P1learn으로 배운 것 정리하기
/learn

여기서 중요한 건 learn이 곧장 파일을 고치지 않는다는 점입니다. 먼저 후보를 보여주고, 사람이 승인한 것만 CLAUDE.md나 문서에 최소한으로 반영합니다. 되돌리기 어려운 규칙일수록 이 승인 단계가 안전장치가 됩니다.

마무리

  • clarify -> prd -> implement -> verify -> pr -> learn에서 learn은 이번 작업의 교훈을 다음 작업의 기본값으로 옮기는 마지막 고리입니다.
  • 좋은 Skill을 가져오는 것보다 중요한 건, 내 프로젝트에서 반복되는 실수와 검증 방식을 계속 프로젝트 파일에 남겨두는 것입니다.
