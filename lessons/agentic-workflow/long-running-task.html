chapter Blesson B.5privateworkbench

에이전틱 워크플로우

긴 작업 태워보기

여러 사용자 스토리가 섞인 작업을 워크플로우를 통해 개발한다

얻어갈 것

  • 여러 사용자 스토리를 하나의 PRD로 묶기 전에 모호한 지점을 구체화합니다.
  • PRD, 구현, 검증, 코드리뷰, PR까지 이어지는 체크포인트를 잡습니다.

1. /clarify: 요구사항 명확하게 하기

사용자 스토리는 세 가지입니다: 장소 리뷰, 장소 수정 요청, 새로운 장소 제보.

  • 리뷰 기능: 사용자가 장소에 good / normal / bad 중 하나를 남기고, 본인의 선택을 바꿀 수 있는지 정합니다.
  • 수정 요청: 사용자가 장소 정보의 어떤 필드를 고쳐달라고 요청할 수 있는지, 요청 상태를 누가 어떻게 보는지 정합니다.
  • 새 장소 제보: 사용자가 어떤 최소 정보로 장소를 제보하고, 승인 전에는 어디에도 노출되지 않게 할지 정합니다.
P1clarify
/clarify 아래 세 사용자 스토리를 구현하려고 한다

- 사용자가 기존 장소를 good / normal / bad 로 리뷰할 수 있다
- 사용자가 기존 장소 수정 요청을 보낼 수 있다. 기본 필드로 사진과 메모를 받게 한다.
- 사용자가 새로운 장소를 제보할 수 있어야 한다. 기본 필드로 네이버 URL, 사진 여러 장과 메모를 받게 한다

모두 로그인이 된 상태여야 한다.

2. /prd: 하나의 PRD로 묶기

  • clarify에서 정리한 답변을 하나의 PRD로 묶습니다.
  • PRD에는 세 사용자 스토리, 공통 데이터 구조, 권한, 완료 조건, 검증 방식을 함께 둡니다.
P2PRD 만들기
/prd 기본 요구사항과 방금 clarify에서 정리한 내용을 바탕으로 하나의 PRD를 만들어줘

3. PRD 리뷰하기

  • PRD를 바로 구현하지 말고 먼저 위험한 결정과 빠진 조건을 봅니다.
  • 특히 데이터베이스 스키마 마이그레이션(Database schema migration), 스토리지 API(Storage API) 활용, 로그인/권한, 운영자 확인 흐름을 확인합니다.
  • 사람이 결정해야 할 항목이 남아 있으면 구현 전에 PRD를 고칩니다.

4. /implement: PRD 실행하기

리뷰가 끝난 PRD를 기준으로 구현을 시작합니다.

P3PRD 구현
/implement 이 PRD를 기준으로 구현해줘.

- 완료 조건을 체크리스트로 만들고 꼼꼼하게 확인해줘.
- 사람 검증이 반드시 필요한 지점이 있다면 멈추고 물어봐줘.

5. 실제 검증 + code-review

implement가 구현하면서 이미 검증을 한 차례 거칩니다. 그래서 여기서는 두 갈래 중 하나를 고르면 됩니다.

  • 더 꼼꼼히 다시 보고 싶으면 verify 스킬로 구현과 분리해 독립적으로 검증합니다.
  • 그 정도까진 아니면, implement가 끝낸 검증 결과를 바로 확인하고 /code-review로 한 번 더 훑습니다.

/code-review는 Claude Code의 공식 기능입니다. 구현자가 놓친 요구사항이나 위험한 diff를 변경 범위 기준으로 다시 잡아줍니다.

P4검증과 코드리뷰
/code-review

6. /pr: PR 올리기

  • 검증과 코드리뷰가 끝난 뒤에 PR을 올립니다.
  • PR 본문에는 구현 범위, 실행한 검증, 사람이 봐야 할 화면, 남은 리스크를 적습니다.

마무리

  • 이번 레슨에서는 clarify -> PRD -> implement -> 실제 검증 + code-review -> PR 흐름으로 긴 작업을 끝까지 태워봅니다.

지금은 각 단계를 직접 하나씩 태웠지만, 이 흐름 자체도 더 자동화할 수 있습니다. 어디까지 사람이 확인하고 어디부터 AI에게 맡길지는 뒤의 Agentic Engineering 파트에서 더 다룹니다.
