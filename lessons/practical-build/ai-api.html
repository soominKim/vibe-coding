AI API 연결하기 (OpenAI)

OpenAI API로 느좋카페에 AI 카페 추천 챗봇을 붙이는 큰 흐름을 이해하고, SDK와 API의 차이까지 정리합니다.

얻어갈 것

느좋카페에 OpenAI API 기반 AI 카페 추천 챗봇을 붙이는 큰 흐름을 이해합니다. 코드를 직접 짜기보다, AI API가 무엇이고 어떤 순서로 동작하는지 그림을 잡는 데 집중합니다. (이번 레슨은 OpenAI API 기준입니다.)

AI API란? — 똑똑한 모델을 ‘빌려 쓰기’

OpenAI 같은 회사는 이미 잘 학습된 AI 모델을 서버에 올려 두고, 누구나 요청(request)을 보내면 응답(response)을 돌려주는 창구를 열어 뒀습니다. 이 창구가 API입니다. 우리는 모델을 직접 만들거나 학습시킬 필요 없이, 요청만 보내서 결과를 빌려 씁니다.

큰 흐름 — 질문 한 번에 무슨 일이 일어나나

사용자가 챗봇에 “조용하고 콘센트 많은 카페 추천해줘”라고 입력하면:

  1. 브라우저(채팅창)가 그 메시지를 우리 서버로 보냅니다.
  2. 우리 서버가 사용자 메시지 + data/cafes.json의 카페 데이터를 묶어 OpenAI API로 보냅니다.
  3. OpenAI 모델이 조건에 맞는 카페를 골라 추천 답변을 생성합니다.
  4. 우리 서버가 그 답변을 받아 채팅창에 보여주고, 추천 카페를 지도와 연결합니다.
[사용자] → [우리 서버 (+ cafes.json)] → [OpenAI 모델]
                                            │
[사용자에게 표시] ← [우리 서버] ← ── 추천 답변 ──┘

핵심은 브라우저가 OpenAI를 직접 부르지 않고 우리 서버를 거친다는 점입니다. 이유는 아래 ‘API 키’에서 설명합니다.

1. 결제 등록과 API 키 발급

OpenAI API는 사용한 만큼 과금되므로, 먼저 결제 수단을 등록하고 크레딧을 충전해야 합니다. platform.openai.com에서 결제를 등록한 뒤 API 키를 발급받습니다.

  • 발급된 키는 생성 직후 한 번만 전체가 보이므로 안전한 곳에 복사해 둡니다.
  • API 키는 비밀번호와 같습니다 — 코드나 깃허브에 올리면 안 됩니다.

2. 모델 고르기

작업에 맞는 모델을 고릅니다. 모델마다 성능·속도·가격이 다릅니다. 종류와 특징은 OpenAI 모델 문서에서 확인할 수 있습니다. 이번 실습에서는 gpt-6-luna 모델을 Responses API로 연동합니다.

3. 키를 .env.local에 저장

발급받은 키는 .env.local에 OPENAI_API_KEY로 저장하고, 서버에서만 사용합니다. 그래야 브라우저(사용자)에게 키가 노출되지 않습니다. 카카오맵 키처럼 브라우저에 노출되는 NEXT_PUBLIC_ 키와 다릅니다.

# .env.local
NEXT_PUBLIC_KAKAO_MAP_KEY=카카오맵_JavaScript_키
OPENAI_API_KEY=여기에_발급받은_OpenAI_API_키

.env.local은 반드시 .gitignore에 넣어 깃허브에 올라가지 않게 합니다. 나중에 Vercel로 배포할 때는 같은 값을 배포 환경의 환경변수로 등록하면 그대로 동작합니다.

4. 프롬프트로 구현 요청하기

준비가 됐으면 아래 프롬프트로 챗봇 구현을 요청합니다. 동작·데이터·모델·보안·배포 요구사항을 한 번에 정리해 전달하는 것이 핵심입니다.

P1OpenAI 추천 챗봇 구현 요청
현재 느좋카페 서비스에 OpenAI API 기반 AI 카페 추천 챗봇을 추가해줘.
1. 오른쪽 하단에 둥둥 떠 있는 채팅 아이콘을 만들고, 클릭하면 채팅창이 열리게 해줘.
2. 사용자가 자연어로 원하는 조건을 말하면 대화를 통해 취향을 파악하고 적합한 카페를 추천해줘.
3. 기존 data/cafes.json 데이터를 활용하고, 실제 등록된 카페만 추천해줘. 추천 이유도 간단히 설명해줘. 데이터에 없는 정보는 지어내지 마.
4. 추천 카페를 클릭하면 카카오맵에서 해당 위치와 상세 정보를 보여줘.
5. **OpenAI 모델은 gpt-6-luna**를 사용하고 Responses API로 연동해줘. 비용 절감을 위해 reasoning.effort는 none으로 설정해줘.
6. API Key는 .env.local에 OPENAI_API_KEY로 저장하고, 서버에서만 호출해줘. .env.local은 .gitignore에 포함해줘.
7. 기존 기능을 유지하고 모바일에서도 자연스럽게 작동하도록 구현해줘.
8. 추후 GitHub에 업로드하고 Vercel로 배포할 예정이므로, 배포 환경에서도 환경변수 설정만으로 정상 작동하도록 해줘.
최대한 간단하게 구현하고, 불필요한 기능이나 복잡한 구조는 추가하지 마. 로컬 개발 포트는 3030으로 유지해줘.

SDK와 API는 뭐가 다를까

마지막으로, 자주 헷갈리는 SDK와 API의 차이를 정리합니다.

  • API — 서버에 보내는 요청 규칙입니다. 정해진 주소(엔드포인트)에 정해진 형식으로 HTTP 요청을 보내면 응답이 옵니다. 언어·도구와 상관없이 HTTP만 보낼 수 있으면 됩니다.
  • SDK — 그 API를 특정 언어에서 쉽게 쓰라고 감싸 놓은 라이브러리입니다(예: openai npm 패키지). 내부적으로는 결국 같은 API를 호출합니다.

비유하면 API는 콘센트 규격, SDK는 그 규격에 맞춘 충전기입니다. 규격만 맞으면 직접 선을 연결(API)해도 되고, 만들어진 충전기(SDK)를 꽂아 써도 됩니다.

  • 앞서 카카오맵은 브라우저에서 지도를 그리려고 JavaScript SDK를 썼습니다.
  • OpenAI는 키를 숨겨야 하므로 서버에서 API(또는 서버용 openai SDK)로 호출합니다.
