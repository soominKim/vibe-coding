배포하기

나만의 도메인 설정하기

도메인 이름과 DNS 레코드로 호스팅 서비스 연결 상태를 확인합니다

얻어갈 것

  • 도메인, 서브도메인, DNS 레코드의 기본 뜻을 잡습니다.
  • 호스팅 서비스와 도메인 관리 서비스에서 무엇을 맞춰야 하는지 봅니다.

DNS 구조

DNS(Domain Name System)는 사람이 읽는 도메인 이름을 실제 서비스 위치로 이어 주는 분산 주소록입니다.

  • 도메인(domain)은 사람이 읽기 쉬운 주소입니다. 예를 들어 myservice.com 같은 이름입니다.
  • 호스팅 서비스에 배포된 사이트는 기본 URL이 있지만, DNS를 설정하면 내가 산 도메인으로 접속하게 만들 수 있습니다.
  • DNS에는 내부적으로 여러 네임서버(nameserver)들이 존재하며, 이 네임서버를 통해서 도메인이 변환됩니다.
  • DNS 레코드는 네임서버에 적어 두는 실제 연결값입니다. 예를 들어 myservice.com을 Vercel 쪽 주소로 보내는 설정입니다.

도메인 연결에서 볼 화면

보통은 두 화면만 보면 됩니다.

  • 호스팅 서비스: "이 도메인을 내 프로젝트에 붙이겠다"고 추가하고, 필요한 DNS 값을 확인합니다. 이 레슨에서는 Vercel이 예시입니다.
  • 도메인 관리 서비스: 내가 산 도메인의 DNS 레코드나 네임서버를 수정합니다. 예: GoDaddy, 가비아, Spaceship.
  • 대부분은 도메인을 산 서비스 안에 도메인 관리 화면도 같이 있습니다.

네임서버

네임서버(nameserver)는 특정 도메인의 DNS 레코드를 들고 응답하는 서버입니다. 도메인 관리 화면에서 "네임서버를 바꾼다"는 말은 이 도메인의 레코드를 어느 서비스의 네임서버가 맡을지 바꾸는 뜻입니다.

  • 도메인을 처음 사면 보통 구매처의 기본 네임서버가 잡혀 있습니다.
  • 이번 실습처럼 Vercel에 DNS까지 맡기려면, 도메인 관리 서비스에서 네임서버를 Vercel이 알려준 값으로 바꿉니다. 예: ns1.vercel-dns.com, ns2.vercel-dns.com.
  • 네임서버를 바꾸면 그 뒤부터는 예전 구매처 화면이 아니라 새 도메인 관리 서비스에서 A, CNAME, TXT 레코드를 고칩니다.

도메인 이름 읽기

도메인 화면에서는 비슷한 단어가 자주 나오니, 처음에는 아래 정도만 구분하면 됩니다.

이름예시의미
루트 도메인myservice.com내가 산 기본 도메인
서브도메인www.myservice.com기본 도메인 앞에 이름을 붙인 주소

대부분의 서비스는 myservice.com과 www.myservice.com을 둘 다 연결합니다. 하나만 연결하면 어떤 사람은 접속되고, 어떤 사람은 접속이 안 되는 것처럼 보일 수 있습니다.

레코드 감각

DNS 레코드는 "이 이름으로 들어오면 어디로 보낼지"를 적어 둔 줄입니다. 전부 외울 필요는 없고, 호스팅 서비스가 요구하는 값을 현재 DNS를 관리하는 화면에 그대로 넣는다고 보면 됩니다.

레코드자주 쓰는 곳의미
A루트 도메인도메인을 특정 IP 주소로 보냅니다.
CNAMEwww 같은 서브도메인한 도메인 이름을 다른 도메인 이름으로 보냅니다.
TXT소유권 확인"이 도메인을 내가 관리한다"는 확인값을 넣을 때 자주 씁니다.

Vercel에서 할 수 있는 두 가지

Vercel에서 커스텀 도메인을 쓰는 방법은 크게 둘입니다.

방법언제 쓰나어디서 관리하나
Vercel Domains에서 직접 사기새 도메인을 아직 사지 않았을 때Vercel에서 도메인과 DNS를 같이 관리
외부 도메인 관리 서비스에서 Vercel 네임서버로 변경하기이미 GoDaddy, 가비아, Spaceship 같은 곳에서 도메인을 샀을 때구매처에서는 네임서버만 바꾸고, 이후 DNS 레코드는 Vercel에서 관리

자주 나는 사고

  • www.example.com만 연결하고 example.com은 빠뜨리는 경우가 있습니다.
  • DNS를 수정했는데 반영까지 시간이 걸려 바로 안 되는 것처럼 보일 수 있습니다.
  • 예전에 넣어 둔 레코드와 Vercel이 요구하는 레코드가 충돌할 수 있습니다.
  • 네임서버를 Vercel로 바꾼 뒤에도 예전 도메인 관리 서비스에서 레코드를 고치면 반영되지 않을 수 있습니다.

AI 브라우저로 도메인 연결하기 (단계별 프롬프트)

아래는 Aside 같은 AI 브라우저에 그대로 복붙해서 쓸 수 있는 단계별 프롬프트입니다. 각 단계에서 해당 서비스 화면(Vercel · GoDaddy · Kakao Developers · Supabase)을 열어 둔 상태로 프롬프트를 주면, AI가 현재 화면을 읽고 설정을 도와줍니다.

예시는 도메인을 superchico.xyz로 가정합니다. 본인 도메인으로 바꾸고, {} 부분은 각 서비스가 실제로 보여주는 값(Vercel이 안내한 A 레코드 IP·CNAME 대상 등)으로 채워 넣으세요.

단계 1 · Vercel에 도메인 등록

Vercel 프로젝트의 Settings > Domains 화면을 열어 둔 상태로 입력합니다.

P1Vercel 도메인 등록
지금 Vercel 프로젝트의 Settings > Domains 화면이야. 내가 구매한 도메인을 이 프로젝트에 등록해줘.

- 루트 도메인: superchico.xyz
- 서브도메인: www.superchico.xyz

둘 다 추가하고, 각각에 필요한 DNS 레코드 값(루트 도메인용 A 레코드 IP, www용 CNAME 대상)을 그대로 알려줘.

단계 2 · GoDaddy에 DNS 레코드 입력

단계 1에서 Vercel이 알려준 값을 GoDaddy DNS 관리 화면에 넣습니다.

P2GoDaddy DNS 레코드 추가
지금 GoDaddy DNS 관리 화면이야. Vercel이 등록됐고, 아래 레코드를 추가해줘.

A 레코드
- 이름(Host): @
- 값(Value): {}

CNAME 레코드
- 이름(Host): www
- 값(Value): {}

기존에 충돌하는 A / CNAME 레코드가 있으면 먼저 알려주고, 어떻게 정리할지도 같이 안내해줘.

단계 3 · 카카오 개발자 콘솔에 도메인 추가

Kakao Developers 콘솔에서 새 도메인을 등록합니다.

P3카카오 콘솔 도메인 추가
지금 Kakao Developers 콘솔이야. 새 도메인으로 서비스가 동작하도록 설정을 업데이트해줘.

- 앱 설정 > 플랫폼 > Web 사이트 도메인에 추가:
  https://superchico.xyz
  https://www.superchico.xyz

- 카카오 로그인 Redirect URI는 Supabase callback 주소를 쓰니 그대로 두고, 새 도메인 때문에 추가로 넣어야 할 값이 있으면 알려줘.

단계 4 · Supabase URL 설정

Supabase Authentication > URL Configuration 화면에서 새 도메인 기준으로 값을 맞춥니다.

P4Supabase Site URL · Redirect URL
지금 Supabase의 Authentication > URL Configuration 화면이야. 새 도메인 기준으로 업데이트해줘.

- Site URL: https://superchico.xyz

- Redirect URLs에 추가:
  https://superchico.xyz/**
  https://www.superchico.xyz/**

기존 로컬 개발용 http://localhost:3030/** 는 지우지 말고 함께 남겨줘.

단계 5 · 앱 환경변수 반영 후 재배포 (빠지기 쉬운 단계)

코드에서 사이트 주소를 환경변수로 쓰고 있다면, 운영 도메인으로 바꾼 뒤 다시 배포해야 로그인 리다이렉트가 새 도메인으로 돌아옵니다.

P5환경변수 · 재배포 확인
지금 Vercel 프로젝트의 Settings > Environment Variables 화면이야. 사이트 기본 주소(예: NEXT_PUBLIC_SITE_URL 같은 값)가 있으면 https://superchico.xyz 로 바꾸고, 바꾼 뒤 재배포가 필요한지 알려줘.

그리고 superchico.xyz / www.superchico.xyz 로 접속했을 때 카카오 로그인까지 정상 동작하는지 확인하는 체크리스트도 정리해줘.

마무리

  • 도메인 설정은 배포된 사이트에 내가 산 이름을 붙이는 작업입니다.
  • 막히면 "Vercel이 요구하는 값"과 "현재 네임서버가 가리키는 도메인 관리 서비스의 값"을 비교하면 됩니다.
  • 런칭/운영 편에서는 배포 후 장애 대응, 롤백, 더 복잡한 자동화 흐름을 이어서 다룹니다.
